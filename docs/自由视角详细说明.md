# Free-angle mode: detailed guide

> This is the full technical guide for Fisher Qwen 2.1 Character & Pose Encode and Fisher Pose & Camera, the original free-angle nodes. For Free Pose mode, see the repository README.

## Prompt format: JSON with orientation and posture

Both nodes output a complete JSON document through their prompt STRING output. The combined encoder passes the same JSON directly to Qwen positive encoding. Existing output order and connections are preserved.

- `rewritten_prompt`: the complete editing instruction, or the final expanded instruction when PE is connected.
- `posture_description`: one line per character, in character/orientation/posture format, calculated from the editor. Empty for scenes without people; camera-only mode requests preservation of the original actions.
- `wh_ratio`: the reduced final output aspect ratio. `ratio_follow` is an empty string.

This combines PE's field structure with a custom posture field; it is not claimed to be an officially required extension. Serialization happens after PE completion or a cache hit and adds no PE call. The editor displays pose/mapping previews. Actual prompt after execution is the JSON actually sent to the model.

## Scene-image cube with no characters

Removing all characters reveals a scene cube. Its image face represents the front; other faces show direction labels. It follows the current camera rotation and distance. It first uses an upstream preview or LoadImage file connected to `reference_image_1`. If none is readable yet, upload a preview on the left. A manually uploaded thumbnail is saved with the scene.

The cube illustrates direction, not the image's true 3D space. It is excluded from mannequin output and PE inputs and is hidden when characters are added.

## Limb stretching and scene-only cameras

Dragging a wrist or ankle beyond its original bone length extends the current limb. Alt+drag adjusts joint length, including shortening. Bone lengths are saved with the workflow and support undo. Resetting to standing restores default proportions.

The final character can be deleted. With zero characters, the editor enters scene-only Camera only mode, retaining orbit and zoom controls. On the combined encoder, connect only `reference_image_1` as the source scene. No mannequin is appended internally; prompts and PE describe only the scene camera, without character actions. On the original separate-output node, connect only the prompt and disconnect the pose image. Add a character at any time to return to posing. Changing the viewpoint does not automatically remove objects from the source image.

## PE reuse and body controls

PE caches the last 16 successful expansions within the loaded CLIP instance. Results are reused when character-image pixels, pose reference, instruction/action data, framing, PE model and output limit are unchanged. Changing the sampling seed or reopening the editor alone does not rerun expansion. Failures are not cached. Restarting ComfyUI or reloading the PE model requires a new first expansion; the cache does not persist across restarts.

Gray shoulder, hip, chest and pelvis points can be dragged, as can the head. The chest bends/leans the upper body around the pelvis; shoulders move the shoulder girdle and arms. Pelvis movement attempts to keep feet planted, but feet move when leg length is exhausted. Torso orientation updates the prompt. Dragging the body surface moves the character; Shift+drag on a joint also moves the whole person. Edits support undo. Skeleton display makes gray points easier to select.

The updated mannequin has a tapered waist/shoulder-back silhouette, varying limb thickness and simplified palms. It remains a plain mannequin without independent finger controls and renders exactly within the output frame.

## Framed 3D mannequin reference

The output renders the 3D mannequin inside the editor's output frame using the current dimensions, camera, placement, distance and crop, without automatically fitting characters. Selection rings, arrows, names and uploaded backgrounds are removed. Final generation size still follows node settings. Body parts outside the frame are excluded; adjust the camera or use Frame all characters for full-body references.

After updating, restart ComfyUI and refresh. Open the editor in an existing workflow and Apply to node once to save the updated mannequin reference. The editor need not remain open. Each application rerenders the current pose and saves the image with the pose state in the workflow.

On first use, open the editor and apply the current frame. For multiple people, choose the corresponding photos and apply again. PE uses thinking off and images with a longest side of at most 1024 pixels. Disconnect `pe_clip` to use deterministic local pose instructions directly.

Place the complete `ComfyUI-Fisher-Pose` folder in `ComfyUI/custom_nodes/`, restart ComfyUI and refresh the browser. The editor itself needs no extra Python packages or model downloads. Search for Fisher nodes; generation and optional PE still require their models.

## Qwen 2.1 combined encoder: recommended

By default, leave `pe_clip` disconnected for direct instructions. The editor builds continuous natural language covering the editing target, character/image mapping, appearance preservation, each character's action, removal of the old pose, camera, background and style. It describes upper-arm/thigh extension, elbow/knee bending, projected hand/foot relationships, and lower-leg inward/outward/cross-body direction. It does not write numeric joint angles or guess specific clothing or object names. Images use `<imageN>` tags and framing is controlled independently. The resulting JSON goes directly to positive encoding without loading PE.

Search for Fisher Qwen 2.1 Character & Pose Encode. It combines editing, reference ordering and the local `TextEncodeQwenImage21` encoder. It requires a ComfyUI version with that encoder, plus the Qwen 2.1 diffusion model, CLIP and VAE.

- Connect character photos in order to `reference_image_1/2/3`, one image per socket, not an image batch. The editor renders/saves the mannequin when applied. It is appended after all character references; with three character images, the mannequin is `<image4>`.
- Add the corresponding character count in the editor. `person_1/2/3_reference` follows the left-side character list. Auto shares one image among multiple people, or maps character 1→image 1, character 2→image 2, character 3→image 3 when multiple images are connected. Manual assignments are available. For a shared group photo, enter identity descriptions such as “the person in red” on the character page.
- Connect Positive, Negative and `latent` to their sampler inputs. Instructions go to positive encoding; negative remains empty. Editor or width/height inputs set the frame, with dimensions divisible by 16.
- Camera-only mode omits the mannequin automatically. Pose mode explicitly replaces the old action and fills the old limb locations while preserving appearance. Combining characters from several photos does not assume any one photo is the original group scene.
- The editor previews reference assignments. Actual prompt after execution shows the text passed to the encoder. This node uses Qwen Chinese edit instructions internally, not the old node's Multiangle LoRA format. Changing the UI language does not translate model instructions.
- Editor uploads remain skeleton-fitting aids. Character appearance images must be connected to the node's IMAGE inputs.

### Relationship to official Prompt Rewrite

Editing instructions follow the [Qwen Image 2.1 prompt conventions](https://github.com/QwenLM/Qwen-Image-2.1/tree/main/prompt_rewrite): `<imageN>` identifiers, explicit image roles, preservation of unchanged attributes and replacement of the target action. Without `pe_clip`, instructions are deterministic. When connected, PE-I2I sees the character images and 3D mannequin, describes the action, and supplies the parsed final instruction to image encoding. Do not route through Generate LTX2 Prompt; it adds a video-specific system template.

Load a `qwen3.5_qwen_image_2.1_pe_i2i` model for PE. Generation CLIP still connects to `clip`; PE-specific CLIP connects to `pe_clip`. They are not interchangeable.

The adapter uses the supplied `system_prompt_edit.txt` and Qwen3.5 chat format, with thinking off. All images are passed in the same order as generation encoding. It accepts complete `rewritten_prompt` JSON and supports older completed thinking blocks. Truncation, nonexistent image references or aspect-ratio suggestions conflicting with the editor stop execution explicitly; raw reasoning is never used as the final prompt. The editor frame is retained, and `wh_ratio` / `ratio_follow` must agree with it instead of silently changing dimensions.

The editor calculates each character's camera-relative facing, inner elbow/knee angles, and projected hand/ankle relationships. Its pose preview and backend follow the same rules. PE receives these facts as action guidance and rewrites them into natural language. Verbatim retention is not required, and omitted or rephrased action descriptions do not by themselves stop generation.

All character and mannequin images sent to PE are proportionally reduced to a longest side of at most 1024 pixels. Small images are not enlarged; no cropping or stretching is applied, and the short side is rounded to whole pixels. Only PE inputs are affected; original images and output framing are preserved. The initial PE configuration used an 8192-token limit, temperature 1, top_p .95, top_k 20, presence_penalty 0 and thinking off, with a prefilled completed empty thinking block for direct final output. Later configurable options are listed below. `pe_max_tokens` supports up to 24000, increasing memory use. Truncation does not silently proceed. PE adds latency and cannot reliably interpret every complex, cropped or overlapping pose; inspect actual generated images.

In the recorded single-person test with thinking off, PE took about 62 seconds and generation about 108 seconds. The mannequin reference improved open-arm and bent-knee matching and removed the original cup-holding action. Facing, clothing and final portrait cropping still differed. This is one sample, not a guarantee of pose accuracy or speed on other hardware.

## Original separate outputs: legacy workflow connections

- Prompt `STRING` → `TextEncodeQwenImage21.prompt`
- Mannequin pose `IMAGE` → `TextEncodeQwenImage21.images.image_2`
- Original character image → `TextEncodeQwenImage21.images.image_1`

In camera-only mode, connect only the prompt and disconnect the pose reference from image_2. Pose-only mode can use the node's prompt or a custom one. Connect both outputs for camera + pose. Changing node mode does not modify workflow links automatically.

Double-clicking may not open the editor; use Open pose & camera editor on the node. Drag joints to pose and empty space to orbit. Set output mode/size, Apply to node, then run the workflow. Closing or canceling discards the current editing session. Scenes and saved cameras are stored in workflow JSON, isolated by node instance. The editor does not need to stay open because the backend reads the mannequin reference saved with the scene.

`extra_prompt` supplies additional requirements without requiring an expansion node. Mannequin dimensions are those in the editor when applied. The plugin's `workflows/` contains only the Free Pose workflow; connect free-angle mode manually as above.

## Supported editing behavior

The mannequin head uses flat eye/front/back markers rather than a protruding nose. A floor arrow points in the character's local forward direction. The character panel shows camera-relative facing and offers Turn 180°, which rotates the entire character and pose and supports undo. A 2D skeleton does not uniquely determine front/back; confirm using the markers.

Facing is calculated separately from the actual camera position, character position and `bodyAngle`. A global back-view camera label does not describe every person's facing. Local +Z is forward; the head currently has no independent orientation. Joint descriptions distinguish character-relative left/right from screen-space left/right. Camera-only mode adds no limb-action requests. The legacy Multiangle LoRA camera format is preserved.

Supports 1–3 people: add/duplicate/delete, selection, separate two-bone IK, body rotation, ground-plane movement, presets and mirroring. Select from the list or click a mannequin. Drag the body to reposition and colored joints to pose without switching modes; Shift+drag on a joint also moves the whole person. All characters share one camera and export as one framed mannequin image. Camera presets, undo and workflow saving include the entire scene. Old single-person scenes migrate automatically, preserving the original two output interfaces.

The character page's Identity in the source image field accepts descriptions such as “the person in red on the left.” Prompts derive mappings from projected mannequin positions. This is textual guidance, not automatic face recognition or identity locking. The original separate-output node uses one group photo as image_1; use the combined encoder above for three independent character photos.

After uploading a reference, Fit skeleton to mannequin accepts standard colored OpenPose body skeletons and older skeleton images exported by this plugin. Body connectivity filters same-color face/finger interference, detects 1–3 people and applies pose, proportions and framing. Failure leaves the scene unchanged; changes support undo.

Selected character only is the default. Select a character, upload a skeleton and fit it. Different references can be applied to each character while preserving others, camera, output dimensions, names, identity descriptions, placement and body rotation. If a reference contains multiple people, choose the source person from left to right after the first detection, then apply again. Poses scale to the existing character and preserve the foot baseline. Only Rebuild scene from full image replaces all characters and resets front camera/framing.

Single-image fitting initializes a 2D plane and cannot recover true depth. Adjust side poses manually. This original free-angle import path does not estimate poses from ordinary photos. With enough body connections, overlapping/cropped joints can be approximately filled, and the UI lists areas to check. These positions are estimates, not recovered depth or exact invisible joints. Insufficient evidence, incompatible colors and ambiguous multi-person connections may still fail.

Fitted poses and each person's bone lengths are saved with the workflow and remain editable. The uploaded image is a visual overlay, is not embedded in the workflow and does not replace image_1. It aligns to the output frame. Skeleton colors/connection order follow [ControlNet's OpenPose drawing implementation](https://github.com/lllyasviel/ControlNet/blob/main/annotator/openpose/util.py). Detection here is implemented locally and does not upload images or download models.

## Camera prompt terminology

Angle bins and terminology follow [ComfyUI-qwenmultiangle](https://github.com/jtydhr88/ComfyUI-qwenmultiangle/blob/master/nodes.py): eight horizontal directions, elevation thresholds −15/15/45 degrees, wide shot for zoom below 2, medium shot from 2 to below 6, and close-up from 6 upward. Directions are relative to the scene front; 90° is right side view, unaffected by the selected character or body rotation.

Choose the format on the Output tab:

- **Chinese edit instructions**: the default for the existing Qwen 2.1 workflow, using the same camera vocabulary and bins.
- **Multiangle LoRA (`<sks>`)**: camera-only mode outputs the original format, for example `<sks> right side view high-angle shot close-up`. Configure a compatible multi-angle LoRA downstream; the plugin neither downloads nor loads it. Combined mode appends English character/mannequin pose-reference guidance.

3D camera distance follows the scale of the character scene, not the source project's image-card distance ratios. Frame all characters can move the camera farther back to keep everyone visible.

These mannequins do not have independent finger posing. Qwen interprets the image as a visual pose reference; actual action/view adherence depends on the model. This plugin does not include ControlNet, call external APIs, install/modify other nodes, or modify ComfyUI core.

Three.js 0.182.0 is bundled locally; see `web/editor/vendor/LICENSE`. The pose editor is independently implemented. Camera terminology/bins reference the MIT project above without copying its node, Vue or Three.js control implementation. Editor sources are directly maintained in `web/editor/studio.mjs`, `state.mjs` and `avatar.mjs`, rather than generated by text replacement from a separate prototype.

## Local sample validation

All 209 supplied skeleton samples were processed: 144 matched complete connections and 65 used approximate completion. All produced editable poses with finite coordinates, and 836 limb-IK drag checks passed. These counts validate conversion/editability, not manually annotated per-joint accuracy or recognition of arbitrary new images.

For zero-character scenes, the source view is horizontal/elevation zero. Prompts describe signed camera orbit and elevation to 0.1° precision; PE organizes the description around those values. They express editing intent, not guaranteed precise 3D reconstruction from one image.

Scene-only mode first builds a general camera instruction, then the connected PE expands it with the source scene image and encodes complete JSON. It describes orbit direction/angle, near/far sides and newly visible space relative to the source without hard-coding scene objects. Both scene and character modes use connected `pe_clip`. Thinking-off behavior, the 1024-pixel PE input limit and caching remain. Connect `pe_clip` on the combined encoder; leaving it disconnected still supports direct prompts.

## Canvas camera template, PE options and separate preview

Scene-camera instructions use AIFISHER Canvas's original natural-language template to state the subject view and precise camera parameters before PE expansion. Complete JSON is retained. Added options are `presence_penalty` (default 1.5), `thinking` (default false), `use_default_template` (default true; false retains only JSON output-format requirements), and `mtp` (default auto; choices off/2/3/4/5). Changing any option invalidates PE cache reuse. MTP requires matching model weights.

Both nodes append a Camera preview IMAGE output while preserving existing output indexes. The preview is captured from the editor's output frame, including the scene cube when there are no characters, with longest side 1024 and the frame's aspect ratio. It is for comparison only and is not sent to PE or image encoding. Old workflows must open the editor and apply once to create the separate preview. Before that, an instruction image asks for reopening/application instead of reusing an old mannequin reference without the cube. After upgrading, Ctrl+F5, reopen and apply. Restart ComfyUI and refresh to load the new parameters and output sockets.

## Qwen 2.1 GGUF encoder

Fisher Qwen 2.1 GGUF CLIP Loader requires an installed ComfyUI-GGUF. Select the Qwen3-VL-8B language GGUF as `clip_name` and its matching F16 mmproj as `vision_source`. The vision component can also be read from a complete Qwen3-VL-8B safetensors file. Place both files in `models/text_encoders`. Connect CLIP to the Character & Pose Encode node's `clip`, keeping the existing `pe_clip` connection. Restart ComfyUI to load the new node.

The adapter supports Qwen3-VL deepstack and two-frame patch weights and uses Qwen 2.1's official 4096-dimensional encoding path instead of cropping Klein's 12288-dimensional output. The matching Heretic GGUF + mmproj passed reference-image encoding and a 320×192 one-step sampling compatibility check. A full generation-quality comparison has not been performed.
